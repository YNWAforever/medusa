# Medusa Admin Storefront Link Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use the checkbox syntax - [ ] for tracking.

**Goal:** Add a global Medusa Admin top-bar link that opens the configured Fotomax storefront home at /zh-HK in a new tab.

**Architecture:** Extend the existing Medusa runtime environment resolver with a storefrontUrl value, pass it into Medusa's admin.storefrontUrl configuration, and let a custom Admin widget consume the build-time __STOREFRONT_URL__ global. Keep URL joining in a small pure helper so trailing-slash behavior is unit-tested independently of the Admin renderer.

**Tech Stack:** Medusa 2.17.2, TypeScript, React 18, @medusajs/admin-sdk, @medusajs/ui, @medusajs/icons, Vitest 3, npm workspaces.

## Global Constraints

- Keep the storefront origin in MEDUSA_STOREFRONT_URL and pass it through admin.storefrontUrl.
- Local and test environments may use http://localhost:3000; preview, staging, production, and other non-local environments must provide MEDUSA_STOREFRONT_URL.
- Use the default Traditional Chinese locale path /zh-HK; do not add a locale picker or change storefront routing.
- Render the action in the global topbar injection zone with the label Open storefront and an external-link indicator.
- Open the link with target="_blank" and rel="noopener noreferrer".
- Do not pass Admin authentication or customer session state to the storefront.
- Do not modify the pre-existing .superpowers/sdd/progress.md worktree change.
- Run implementation commands from C:\Users\laich\Documents\fotomax\.worktrees\fotomax-storefront.

## Non-Goals

- No custom Admin route or dashboard fork.
- No locale picker, customer preview, or draft-content workflow.
- No Admin authentication handoff or customer session propagation.
- No Store API request or database mutation from the widget.

## Reference Surface

- Medusa admin.storefrontUrl: https://docs.medusajs.com/learn/configurations/medusa-config
- Medusa Admin environment globals: https://docs.medusajs.com/learn/fundamentals/admin/environment-variables
- Medusa Admin widget injection zones: https://docs.medusajs.com/resources/admin-widget-injection-zones

## Alternatives Not Scheduled

- Configuration-only support would expose Medusa's existing storefront-aware URL behavior but would not provide the requested visible global action.
- A custom Admin route or dashboard fork would add maintenance without improving a single external navigation link.

Locale-aware navigation, customer preview links, authenticated preview sessions, and context-sensitive record links remain deferred until they have separate requirements.

Create apps/medusa/src/admin/storefront-url.ts with:

~~~ts
import { defaultLocale } from "@fotomax/shared"

export const defaultStorefrontLocalePath = "/" + defaultLocale

export function storefrontHomeHref(storefrontUrl: string): string {
  const normalizedOrigin = storefrontUrl.trim().replace(/\/+$/, "")

  if (!normalizedOrigin) {
    throw new Error("Storefront URL must not be empty")
  }

  return normalizedOrigin + defaultStorefrontLocalePath
}
~~~

import { defineWidgetConfig } from "@medusajs/admin-sdk"
import { OpenRectArrowOut } from "@medusajs/icons"
import { Button } from "@medusajs/ui"

import { storefrontHomeHref } from "../storefront-url"

export default function StorefrontLink() {
  if (!__STOREFRONT_URL__) {
    return null
  }

  return (
    <Button asChild size="small" variant="transparent">
      <a
        href={storefrontHomeHref(__STOREFRONT_URL__)}
        target="_blank"
        rel="noopener noreferrer"
      >
        <span>Open storefront</span>
        <OpenRectArrowOut aria-hidden="true" />
      </a>
    </Button>
  )
}

export const config = defineWidgetConfig({
  id: "fotomax:storefront-link",
  zone: "topbar",
})
